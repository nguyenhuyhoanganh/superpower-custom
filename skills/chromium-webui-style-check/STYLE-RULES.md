# Chromium WebUI Style — Condensed Reference

Distilled from the Chromium Web Style Guide plus the Google HTML/CSS,
TypeScript, and JavaScript guides. Use this as the rubric for the manual part
of the review; the mechanical part is handled by `check-style.sh`.

Sources:
- Chromium Web Style Guide: `styleguide/web/web.md`
- ECMAScript features in Chromium: `styleguide/web/es.md`
- Google HTML/CSS Style Guide: https://google.github.io/styleguide/htmlcssguide.html
- Google TypeScript Style Guide: https://google.github.io/styleguide/tsguide.html
- Google JavaScript Style Guide: https://google.github.io/styleguide/jsguide.html

## Foundations
- Separate content (HTML) / styling (CSS) / logic (TS). No inline `style=` or
  `onclick=` (Polymer `on-click` bindings are the documented exception).
- New WebUI code is written in TypeScript.
- 2-space indentation; 80-column limit; +4 spaces on wrapped continuation lines.
- UTF-8, no BOM; lowercase for markup/attrs/selectors/properties/values.

## HTML
- `<!doctype html>`, `<html dir="$i18n{direction}">`, `<meta charset="utf-8">`.
- Element IDs use `dash-form` (exception: `camelCase` in Polymer/Lit for `this.$.id`).
- Localize all strings with `$i18n{}`; `$i18n{}` keys are `camelCase`.
- Double-quote attributes.
- Don't self-close void tags: `<input type="radio">`, not `<input ... />`.
  Custom elements and `<iframe>` must be closed.
- Use `<button>`, not `<input type="button">`. No `<br>`. No spacing-only `<div>`.
- `<table>` only for tabular data.
- Don't use `<label for=...>`: nest the `<input>` in the `<label>`, or use
  `aria-labelledby` for accessibility-only labels.

## CSS
- One selector per line; opening brace on the last selector's line.
- One declaration per line, 2-space indent, trailing semicolon.
- Alphabetize properties; `-webkit-` first (alphabetical), `--variables` alphabetical.
- Space after the `:`; shorthand where possible.
- Omit units on zero (`left: 0;`), except `0%` in percentage lists / `@keyframes`.
- Single quotes for strings; no quotes around `url()` unless a `data:` URI.
- Class names in `dash-form`; don't make a class for a single element — use the ID.
- Sub-second durations in ms: `200ms`, not `0.2s`.
- `::` for pseudo-elements. Scalable `font-size` units (`%`/`em`).
- No CSS Mixins (`@apply` / `--mixin: {}`) — use Shadow Parts, CSS vars, or classes.
- Colors: prefer `rgb()/rgba()` decimals; gray shades like `#333` ok; `#rgb` shorthand.
- No embedded data URIs — relative path or `chrome://resources/...`.
- RTL: `margin-inline-start`, `padding-inline-end`, `text-align: start/end`;
  otherwise set both `[dir='ltr']`/`[dir='rtl']` or prefix `html[dir='rtl']`.
- Avoid `!important`; prefer specificity.

## TypeScript
- Google TS guide + `es.md` + Chromium additions below.
- `$('element-id')` over `document.getElementById`.
- Single quotes (clang-format enforces).
- `event.preventDefault()` over `return false`.
- No `?.` just to silence "possibly null" — use `assert()`. Avoid `?.` chains
  that hide where a null came from.
- No `async` without `await` (return `Promise.resolve(...)` instead).
- No unnecessary non-null `!`. No `any` to dodge errors — use a real type or `unknown`.
- `Number.isNaN()` over global `isNaN()`.
- `assertNotReachedCase()` in the default of an exhaustive enum switch.
- Don't re-export imports from other files (bundle entry points excepted).
- `===`/`!==`; `== null` allowed to cover null+undefined.
- No `var`; `const` by default, `let` when reassigned.
- Naming: `lowerCamelCase` vars/functions/props; `UpperCamelCase` types/classes/enums;
  `CONSTANT_CASE` module-level constants & enum members.

## Polymer
- Lit is preferred for new code; Polymer only for documented exceptions
  (direct `iron-list` parent; Settings/Print Preview/Password Manager prefs+model).
- HTML in `.html`, logic in same-named `.ts`; template via `getTemplate()`
  (generated by `html_to_wrapper`).
- Class-based custom elements; member order: `is`, `behaviors` (legacy),
  `properties` (public then private), `hostAttributes`, `listeners`/`observers`,
  lifecycle, public methods, then handlers/computed/private.
- `camelCase` element IDs (`this.$.camelCase`; declare the `$` interface in TS).
- Use `this.foo` over `newFoo` args in observers/computed; declare deps at the call site.
- `on-click`, not `on-tap`.
- `dom-if` only for non-trivial subtrees (>10 native els, any custom el, many
  bindings, non-text content); otherwise the `hidden` attribute.
- No new `iron-`/`paper-` deps — use `cr-*` from `ui/webui/resources/cr_elements`
  (`cr-collapse` not `iron-collapse`, `cr-icon` not `iron-icon`). Don't add
  `iron-icons` to `third_party/polymer/`.

## Lit
- Default for new pages and new custom elements on existing pages, except the
  Polymer exceptions above. See `docs/webui/webui_using_lit.md`.

## Grit / build
- Resources packed via `generate_grd`; conditional code via `<if expr="...">`,
  processed by `preprocess_if_expr`. Put `<if expr>` inside comments in `.ts`
  so ESLint/formatter don't choke.
- `<include>` / `flattenhtml` are deprecated — use JS imports and Rollup bundling.
- ESLint runs twice: presubmit (`git cl presubmit --files='path/*.ts'`) and
  build-time type-aware (`:lint_ts`).

## ECMAScript (es.md highlights)
- Allowed: arrow fns, Promise, classes, Map/Set, const/let, destructuring,
  template literals, spread/rest, modules, async/await, optional chaining `?.`.
- "To be discussed" (not default-allowed): generators, iterators, Symbol,
  WeakMap/WeakSet, dynamic import, `Object.values/entries`, `padStart/padEnd`,
  `Array.prototype.includes`.
